## 2. Layer-by-Layer Deep Audit

### Pillar 1: Ingestion & Data Acquisition Layer (`ingestion/`)

- **Boundary Service (`ingestion/boundary_service.py`)**: Fetches city polygon via OSMnx with fallback geocoding queries, enforces CRS `EPSG:4326`, and stores both GeoJSON and Shapefile formats.
- **Satellite Service (`ingestion/satellite_service.py` & `stac_fetcher.py`)**: Connects to Planetary Computer STAC API for Sentinel-2 L2A (Red, Green, NIR, SWIR) and Landsat-8/9 Level-2 TIR (Band 10). Automatically applies radiometric scaling and Kelvin-to-Celsius conversion ($(\text{DN} \times 0.00341802 + 149.0) - 273.15$). Fallback synthetic generators ensure offline pipeline testing reliability.
- **Vector Service (`ingestion/vector_service.py`)**: Ingests OSM layers (`roads`, `buildings`, `water`, `parks`, `vegetation`, `railways`, `landuse`) using `OSM_TAGS` dictionaries.
- **Weather Service (`ingestion/weather_service.py`)**: Queries daily meteorological timeseries (temperature, relative humidity, wind speed, solar radiation, precipitation) from NASA POWER REST API for city centroid.
- **Land Cover & DEM Services (`ingestion/landcover_service.py`, `elevation_service.py`)**: Downloads ESA WorldCover 10m classification and Copernicus 30m DEM rasters.

### Pillar 2: Preprocessing & Feature Engineering Layer (`preprocessing/`)

#### 🔴 Critical Discrepancies Identified:

1. **Broken Import in `preprocessing/preprocessor_pipeline.py`**:
    - `preprocessor_pipeline.py` (Line 19) contains:
        
        ```python
        from preprocessing.grid_generator import GridGenerator
        ```
        
    - **Issue:** No `grid_generator.py` file exists in `preprocessing/`. The actual file is `grid_builder.py` with class `GridBuilder`.
    - **Impact:** Running `python run_preprocessing.py` raises `ModuleNotFoundError: No module named 'preprocessing.grid_generator'`.
2. **Missing `FileManager` Helper Methods**:
    - `preprocessor_pipeline.py` calls:
        
        ```python
        bbox = self.file_manager.get_boundary_bbox()
        p = self.file_manager.get_osm_vector_path(fname)
        ```
        
    - **Issue:** `FileManager` in `storage/file_manager.py` does not define `get_boundary_bbox()` or `get_osm_vector_path()`. Instead, it provides `get_boundary_path()` and `get_vector_path()`.
3. **Vector Layer Filename Mismatch**:
    - `preprocessor_pipeline.py` looks for:
        
        ```python
        osm_files = {
            "water": "waterways.geojson",
            "parks": "green_spaces.geojson",
            "roads": "roads.geojson",
            "buildings": "buildings.geojson"
        }
        ```
        
    - **Issue:** `vector_service.py` saves them as `water.geojson` and `parks.geojson`.
    - **Impact:** `vector_layers["water"]` and `vector_layers["parks"]` fail to load, causing distance metrics to fall back to `0.0`.
4. **Geographic CRS Buffering Warning & Building Density Count Bug**:
    - In `feature_extractor.py`:
        
        ```python
        buffered = grid_gdf.geometry.buffer(0.00045)
        buf_gdf = gpd.GeoDataFrame(geometry=buffered, crs=grid_gdf.crs)
        joined = gpd.sjoin(buf_gdf, buildings, how="left", predicate="intersects")
        counts = joined.groupby(joined.index).size() - 1
        ```
        
    - **Issue A:** Buffering in degrees (`0.00045` deg) distorts buffer geometry and triggers GeoPandas warning.
    - **Issue B:** When performing a left join, a grid cell with 0 intersecting buildings has 1 row with `index_right = NaN` (`size() - 1 = 0`). However, a cell with 1 building also has 1 row (`size() - 1 = 0`). Thus, 1 building is counted as 0 buildings.
    - **Solution:** Reproject to metric UTM before buffering, and count valid right indices: `joined["index_right"].notnull().groupby(joined.index).sum()`.
5. **1D Slope & Aspect Gradient Approximation**:
    - In `feature_extractor.py`:
        
        ```python
        dx = np.gradient(result_gdf["elevation_m"].values)
        dy = np.gradient(result_gdf["elevation_m"].values)
        slope_rad = np.arctan(np.sqrt(dx**2 + dy**2))
        aspect_rad = np.arctan2(-dy, dx)
        ```
        
    - **Issue:** Computing gradients along a 1D dataframe index yields identical $dx$ and $dy$, resulting in a constant aspect angle of $315^\circ$ across the city.
    - **Solution:** Compute 2D spatial slope and aspect directly from the DEM raster or from 2D coordinates before point sampling.
